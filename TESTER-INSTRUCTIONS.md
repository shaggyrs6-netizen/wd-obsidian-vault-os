# Try WD Obsidian Vault OS 0.3.1 alpha

**Alpha test copy · about 20 minutes to start · fictional answers first**

This is an early Obsidian starter vault for returning to work after an interruption. We want to know where the first steps help and where they catch. You can stop at any point. Use made-up notes in a separate folder, away from your own vault.

## 1. Unzip it somewhere new

Create **WD Vault OS Test** in Documents. Put the ZIP there and extract it **into that folder**.

| Computer | Test folder example |
|---|---|
| Linux or macOS | `~/Documents/WD Vault OS Test/` |
| Windows | `Documents\WD Vault OS Test\` |

You should see **START HERE.html** beside a **WD Vault OS** folder. That inner folder is the vault. The product has a new name; this technical folder name stays the same in this alpha. Keep both.

## 2. Start with the HTML page

Double-click **START HERE.html**. Choose **Claude**, **Codex**, or **Continue manually**. Tick **Use fictional test answers** and check for **Mode: Fictional rehearsal** before copying a prompt.

For an assistant route, connect **only the extracted WD Vault OS folder**. Let the assistant check what it can read or save. If it cannot save there, choose the manual route. Uploading a ZIP to a chat does not save notes on your computer.

The assistant should ask before saving to the **exact progress folder**. Later it should preview four starter notes and ask again before creating them. You may decline either step.

**Example:** Plan a paper-star display; fold one star; a small step; one star stands; open the sketch. Choose a guide or say **just basics**. With an assistant, say **“Pause now”** after question two. Start a fresh chat with the same folder and the HTML page's **resume prompt**. Were the first two answers kept?

For **Continue manually**, write in `WD Vault OS/Demonstration/Onboarding rehearsal/Manual notes.md` yourself, save it, then reopen it.

## 3. Open it in Obsidian

After saving something, open Obsidian → **Open folder as vault** → choose the inner **WD Vault OS** folder. For an assistant rehearsal, open `Demonstration/Onboarding rehearsal/MY STARTING POINT.md`. Try its project, handoff and **My workflows** links. Then try **HOME.md → Recent notes**. Manual testers start at **Manual notes.md**.

## 4. Tell us what happened

Email feedback to **shaggyrs6@substack.com** with subject **WD Obsidian Vault OS alpha feedback**. A few lines are enough: your computer and route, first confusing step, what you expected, whether you found your note and next action, and what happened when you returned after a break or changed your mind about a workflow.

Screenshots are optional; check them for private details first. **Do not send your whole vault, full chat transcript, passwords or account keys.** The package collects no feedback automatically.
